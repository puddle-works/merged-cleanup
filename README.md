# Clean up after a merged PR

For merged PRs in the repository of the current directory, report whether each one's worktree and branches are safe to clean up (check), and clean up those that are (clean): remove the worktree, delete the local branch and origin's branch with a lease on the PR's head, and fast-forward main.

## For the user

Your builder will give you a one-line command to run it. It asks for the values below.

| What to enter | Kind | Default |
|---|---|---|
| A PR number to check or clean up; 0 means none named. | integer | `0` |
| Up to 5 more PR numbers, comma-separated, digits only; together with pr at most 5. With none named, the latest 3 merged PRs that still have a worktree at their head. | string | empty |

**You get:** Per PR: its number, title, verdict (clean, primary, dirty, locked, ahead, absent, open, closed, error), worktree, branch and a one-line reason; for clean, each step (remove worktree, delete local branch, delete origin branch, fast-forward main) as done, already done, skipped with why, or failed with the error; then a one-line summary, or "Nothing to clean up" when there is none.

### What a run needs

- The repo is a git repo whose `origin` is on GitHub, and `gh` is signed in
  (`gh auth status`).
- `@swamp/git` and `@webframp/github` installed (the pull brings them), with a
  model instance of each named `git` and `github`:

```bash
swamp extension pull @puddleworks/merged-cleanup
swamp model create @swamp/git git
swamp model create @webframp/github github
```

### Methods

- `check` and `run` are read-only: they say what clean would do per PR.
- `clean` acts on PRs whose verdict is `clean` or `primary`, checking each
  again just before acting, and leaves the rest as they are. For a
  `primary` PR (its branch is checked out in the main checkout) it switches
  that checkout to `main`, or `master` where the repo has no `main`.

With no PR named, "the latest 3 merged PRs" are the first 3 of
`list_prs --state merged` sorted by `updatedAt`, newest first: `list_prs`
gives no merge time. A PR whose worktree and local branch are already gone is
`absent` and clean leaves it alone, origin's branch included, as the spec
(version 2) says; a clean stopped part-way (origin's delete failed) is not
finished by running clean again. Delete origin's branch by hand then.
